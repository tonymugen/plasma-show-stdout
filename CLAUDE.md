# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A KDE Plasma plasmoid that displays stdout from shell scripts. Each script runs on its own thread in a C++17 backend (`TimedModule` for interval polling, `SignalModule` for `RTMIN`-triggered runs) exposed to QML as a plugin.

Current scope: `ScriptOutput` (`plugin/plasma-show-stdout.cpp`) drives an arbitrary, ordered list of modules described by a `std::vector<PSSspace::ModuleSpec>` (each spec: trigger kind, script path, interval, signal number, output-length limit). The QML-facing constructor starts with an **empty** list (via the `defaultSpecs()` helper); the modules are then populated **at runtime** by the config panel, which calls the `setModules(QVariantList)` Q_INVOKABLE. Every module's output is joined with a single, configurable delimiter (default `" | "`) into the single `text` property. A `SignalModule` is triggered with `pkill --signal RTMIN+N <host>`, where `<host>` is the process the plugin is loaded into (`plasmashell`, or `plasmawindowed`/`plasmoidviewer` when testing).

The config panel now edits the **full, ordered module list**: a "Add script" button appends modules and each gets a file picker, a Timed/interval-or-Signal/RTMIN-offset trigger, a per-script output-length limit, and a "Remove" button. A single, user-configurable delimiter joins the module outputs. See the *Package config* subsection under Architecture. The originally planned config features are all implemented.

## Build

Requires: CMake ≥3.21, Qt6 (Core, Qml), Plasma 6 (standalone `Plasma` cmake package), KF6 I18n (`find_package(KF6I18n REQUIRED)` — provides `i18n()` and `ki18n_install()`). ECM is fetched automatically via `FetchContent` if not present on the system. `doxygen` is needed only for the optional `-DBUILD_DOCS=ON` API docs (see *Documentation* below).

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
cmake --install build --component plasmoid  # installs plasma package + QML plugin
```

`--component plasmoid` is required to avoid installing ECM's own cmake files alongside the plasmoid. The `plasma_install_package()` call is not component-aware and installs unconditionally regardless.

Build types: `Release` (default), `Debug`, `Profile`, `Test`.

### ECM via FetchContent

When ECM is not installed system-wide, `CMakeLists.txt` fetches it with `FetchContent_Populate` (populate-only, not `FetchContent_MakeAvailable`). This avoids running ECM's own `CMakeLists.txt`, which would add unwanted install rules and interfere with Qt6 detection. After populating, `ECM_MODULE_DIR`, `ECM_FIND_MODULE_DIR`, `ECM_KDE_MODULE_DIR`, and `ECM_MODULE_PATH` are set manually.

### Qt6 and qtpaths

`find_package(Qt6)` must appear **before** `include(KDEInstallDirs6)` because `KDEInstallDirs6` calls `ecm_query_qt`, which requires Qt6 to already be initialized. On this system `qtpaths6` lives at `/usr/lib/qt6/bin/` (not in `PATH`); `CMakeLists.txt` locates it via `qmake6 -query QT_INSTALL_BINS` and caches it as `QUERY_EXECUTABLE` (unset from cache first to avoid stale Qt5 values).

### Plasma 6

In KDE 6, the Plasma framework is a standalone cmake package (`find_package(Plasma REQUIRED)`), not a component of KF6. Its config file is at `/usr/lib/cmake/Plasma/PlasmaConfig.cmake`.

`package/metadata.json` must use the Plasma 6 format:
- `X-Plasma-API-Minimum-Version`: `"6.0"` — **required** for the real `plasmashell` to accept the applet. Without it, plasmashell's widget explorer classifies the widget as `"This widget was written for an unknown older version of Plasma"` and refuses to add it — even though `plasmoidviewer` (plasma-sdk) loads it fine, because plasmoidviewer does **not** enforce this check. (This bit us: every installed system plasmoid declares this key; the obsolete `X-Plasma-API-Version: "2"` we used originally is **not** a substitute and no current plasmoid uses it.) `X-Plasma-API` defaults to `"plasmoid"` and can be omitted (it must **not** be `"declarativeappletscript"`, the Plasma 5 form, which triggers the same misleading error).
- `KPackageStructure`: `"Plasma/Applet"` — top-level, not nested inside `KPlugin`.

**The "unknown older version of Plasma" error is a catch-all** with at least three distinct causes, all unrelated to the actual Plasma version: (1) missing/wrong API metadata (this section — the widget-explorer rejects it before loading QML, so there's **no QML error in the journal**); (2) a failed QML `import` of the C++ plugin (e.g. plugin installed outside the QML import path — see the system-install gotcha below — or a hyphen in the import URI); (3) `declarativeappletscript` (Plasma 5) API. Diagnostic tip: if the journal shows a QML `import`/load error it's cause 2/3; if it shows **nothing** for the applet on add, it's cause 1 (metadata).

### Tests

Tests use Catch2 (fetched automatically via FetchContent):

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Test -DBUILD_TESTS=ON
cmake --build build
ctest --test-dir build
```

There are **two** test executables, both registered with `ctest` via `catch_discover_tests`. Each compiles the code under test directly rather than linking `plasma_show_stdout`, because `KDECompilerSettings` applies `-fvisibility=hidden` to all targets — without an explicit export annotation, neither `runScript` nor `ScriptOutput` is exported from the shared library.

**`tests`** (`plugin/tests/tests.cpp`, links `Catch2::Catch2WithMain`, compiles `scriptModules.cpp`) — the pure-C++ module layer, kept Qt-free and fast. Covers four areas:

- **`runScript`** (`[runScript]`): non-existent path, stdout capture, empty output, multi-buffer output, stderr isolation, non-executable file.
- **`truncateUtf8`** (`[truncateUtf8]`): short string unchanged, ASCII truncation at the limit, exact-limit kept, zero limit yields empty, codepoints counted not bytes (multi-`"é"`), multi-byte sequences (2-/3-/4-byte, incl. an emoji) never split at the cut boundary.
- **`TimedModule`** (`[TimedModule]`): output written after first execution, truncation to `outputLengthLimit_`, loop termination via stop signal, repeated execution across multiple loop iterations.
- **`SignalModule`** (`[SignalModule]`): output written after trigger, truncation, loop termination via stop signal, repeated execution on successive triggers.

These thread tests use the shared `mutex_` for all synchronization: the test waits on the `signalToMain` raw pointer with a 5-second `wait_for` timeout (so a broken stop mechanism fails fast rather than hanging). Output is read and cleared under the lock to avoid races between test reads and module writes.

**`scriptOutputTests`** (`plugin/tests/scriptOutputTests.cpp`, compiles `plasma-show-stdout.cpp` + `scriptModules.cpp`, links `Qt::Core`/`Qt::Qml`/`KF6::I18n`) — the QML-bridge layer (`[ScriptOutput]`). (Because it compiles the bridge, its `ScriptOutput` ctor installs the `i18n()`-backed message translator; the missing-script case below thus flows through `translateMessage` — with no catalog loaded `i18n()` returns the English msgid, so the assertion is unchanged. The pure `tests` target compiles only `scriptModules.cpp`, never installs a translator, links no Qt/KI18n, and so stays Qt-free.) Constructor-path cases: empty-spec construction (no threads, empty `text`), a timed module's output reaching the `text` property, per-spec output truncation, multiple fragments joined in spec order (`"AAA | BBB"`), the `textChanged` `NOTIFY` signal firing, and a signal module staying idle until `raise(SIGRTMIN+4)` then running (exercising the real `sigaction` → semaphore → `signalWaitLoop_` path). Plus a `hostPid`/`hostName` case (`hostPid` equals `QCoreApplication::applicationPid()` and is > 0; `hostName` is non-empty) and a `setDelimiter` case (default `" | "`, then `" :: "` re-joins the existing fragments to `"AAA :: BBB"` synchronously with no worker restart, then an empty delimiter gives `"AAABBB"`). Runtime `setModules` cases (the QVariant path the config UI uses): starting a timed module at runtime, a **per-entry output limit** honored through the QVariant path (a 10-char-limited fragment clipped while a roomier sibling is not: `"ZZZZZZZZZZ | BBB"`), **two timed modules with a real (60 s) interval** joining as `"AAA | BBB"` (a regression guard — the interval-0 cases re-run instantly and so mask a lost first-update race), a **timed module alongside a signal module** (the timed fragment shows immediately as `"TMD | "`, then `raise(SIGRTMIN+offset)` fills the second to `"TMD | SIG"` — the mixed-kind config that prompted the host-PID hint), **reconfiguring** from script A to script B (B's output appears and A's is gone — exercises `stopModules_` → `startModules_` reuse), an empty list clearing `text`, an empty-`script` entry being skipped, a signal entry carrying `signalOffset` triggered by `raise(SIGRTMIN + offset)`, and a **missing script** (a configured non-empty path that does not exist) surfacing `runScript`'s `"… does not exist"` message through the bridge to `text` rather than being dropped as empty output. Because `ScriptOutput`'s bridge posts updates via `QMetaObject::invokeMethod(Qt::QueuedConnection)`, these tests need a `QCoreApplication` and a serviced event loop: the file links `Catch2::Catch2` (not `…WithMain`) and supplies its own `main()` that owns the `QCoreApplication` for the whole run (created before any test, destroyed before the exit-time leak check). A `pumpUntil(pred, timeout)` helper services the event loop with a 5-second cap, mirroring the module tests' fail-fast convention. The signal cases install the process-wide handler and `sem_init`/`sem_destroy` per construction, so they must run sequentially (Catch2's default — do not enable parallel `ctest -j` for this target).

### Localization

All user-facing QML strings are wrapped in `i18n(...)`, and the two backend error strings are localizable via the translation hook (see Architecture). The translation domain is `plasma_applet_com.github.tonymugen.plasma-show-stdout`, set with `-DTRANSLATION_DOMAIN=…` — applied to the library via `target_compile_definitions` (the file-scope `add_definitions(TRANSLATION_DOMAIN …)` runs **after** the library target is created, so it would not reach it; it does still cover the test targets, which are defined later).

`./Messages.sh` extracts every string into `po/<domain>.pot` with `xgettext` (it follows the KDE "scripty" convention — honoring `$XGETTEXT`/`$podir` if set — but also runs standalone, writing `po/` from the project root so the `.pot` records project-relative locations). QML is extracted as C++ (`--language=C++`), which is how Plasma applet `i18n()` calls are picked up. `CMakeLists.txt` calls `ki18n_install(po)` (guarded on `po/` existing), a no-op until a translated `po/<lang>/<domain>.po` is added. No actual translations ship yet — the project is translation-*ready*. (Note: `metadata.json`'s `Name`/`Description` are **not** yet localized; that needs `Name[xx]`/`Description[xx]` keys, normally generated from `.po` by KDE tooling.)

### Documentation

Doxygen HTML API docs for the C++ plugin are opt-in via `-DBUILD_DOCS=ON` (gated on `PROJECT_IS_TOP_LEVEL AND BUILD_DOCS`, like the tests). The build lives in `plugin/docs/` (added with `add_subdirectory(plugin/docs)`):

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_DOCS=ON
cmake --build build --target Doxygen
```

`plugin/docs/CMakeLists.txt` `configure_file()`s `Doxyfile.in` → `Doxyfile` (substituting `@DOXYGEN_INPUT_DIR@`, `@DOXYGEN_OUTPUT_DIR@`, `@README_FILE@`, `@AWESOME_CSS_DIR@`), then a `Doxygen` custom target (`ALL`) runs `doxygen`. Input is the public headers (`plugin/*.hpp`, non-recursive, `FILE_PATTERNS = *.hpp`, `EXTRACT_ALL = NO`); `README.md` is the mainpage (`USE_MDFILE_AS_MAINPAGE`). The [doxygen-awesome-css](https://github.com/jothepro/doxygen-awesome-css) theme is fetched via `FetchContent` and wired through `HTML_EXTRA_STYLESHEET`. Output is **in-source** at `plugin/docs/doxygen/html/`; that dir and the generated `Doxyfile` are git-ignored — only `Doxyfile.in` (and `CMakeLists.txt`) are tracked.

**Gotcha (fixed):** `Doxyfile.in` references `@AWESOME_CSS_DIR@/doxygen-awesome.css`, so the CMake variable must be the **directory** (`set(AWESOME_CSS_DIR ${awesome_SOURCE_DIR})`), not the file path — otherwise the stylesheet resolves to `/doxygen-awesome.css`, doxygen prints `error: Style sheet … does not exist!` (non-fatal, so the target still "builds cleanly"), and the awesome theme is silently dropped. Doxygen also warns about undocumented compounds (`ScriptOutput`, `ShowStdoutPlugin`, the `Q_PROPERTY`s) because `EXTRACT_ALL = NO` — those are doc-coverage gaps, not build failures.

### Running locally

After `cmake --install build --component plasmoid` (with `-DCMAKE_INSTALL_PREFIX=~/.local` for a user install), the Plasma package side typically also needs `kpackagetool6` because `plasma_install_package()` under a user prefix does not always land the package where `plasmashell`/`plasmawindowed` searches:

```bash
kpackagetool6 --upgrade package/ --type Plasma/Applet  # use --install on first run
QML_IMPORT_PATH=~/.local/lib/qml plasmawindowed com.github.tonymugen.plasma-show-stdout
```

`QML_IMPORT_PATH` is required so the C++ plugin (installed under the user QML dir) is discoverable. To avoid setting it per-invocation — and to make the widget loadable from `plasmashell`'s "add widgets" panel — persist it via `~/.config/plasma-workspace/env/qml-import-path.sh` and restart `plasmashell`.

Note that the argument to `plasmawindowed` is the **KPackage applet ID** (with hyphens), not the QML module URI.

**Testing the config dialog:** `plasmawindowed` does **not** expose the applet context menu / "Configure" action (right-clicking the windowed widget produces no menu at all), so it cannot reach the config UI — use it only for the widget's own display. To test configuration use `plasmoidviewer` (from the `plasma-sdk` package), which has an explicit *Configure* toolbar button:

```bash
QML_IMPORT_PATH=~/.local/lib/qml plasmoidviewer -a com.github.tonymugen.plasma-show-stdout
```

(The alternative is the real `plasmashell`: add the widget to a panel/desktop and right-click → *Configure*.) Plasma caches package metadata, so when a structural change isn't picked up — e.g. config files added to an already-installed applet — rebuild the cache (`kbuildsycoca6 --noincremental`), clear the host's compiled-QML cache (`~/.cache/plasmoidviewer/qmlcache`, `~/.cache/plasmawindowed/qmlcache`, and for the real shell `~/.cache/plasmashell/qmlcache`), and/or bump `metadata.json`'s `Version`.

### System-wide install (for testing in the real plasmashell)

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build
sudo cmake --install build           # installs BOTH plugin and package; no --component needed at /usr
rm -rf ~/.cache/plasmashell/qmlcache && kbuildsycoca6 --noincremental
kquitapp6 plasmashell && kstart plasmashell   # then Add Widgets… → "show-stdout"
```

At a `/usr` prefix the C++ plugin lands in `/usr/lib/qt6/qml/...` — a **default** Qt6 import path on this distro (where the system KDE QML plugins live, e.g. `/usr/lib/qt6/qml/org/kde/...`), so **no `QML_IMPORT_PATH` is needed**, and a full `cmake --install` (no `--component`) places exactly the plugin + package with no stray ECM files.

**Gotcha (cost real time once):** `KDE_INSTALL_QMLDIR` is a *cached* ECM variable. If a `build/` dir was first configured with `-DCMAKE_INSTALL_PREFIX=~/.local` (which resolves it to `lib/qml`) and you later just re-run cmake with `-DCMAKE_INSTALL_PREFIX=/usr`, the cached `lib/qml` is **not** recomputed — so the plugin installs to `/usr/lib/qml` (NOT a default import path here), `plasmashell` can't resolve `import com.github.tonymugen.plasmashowstdout`, and the widget fails to add with the misleading *"written for an unknown older version of Plasma"* error (same symptom as a metadata rejection; it's really a failed QML `import`). Fix: configure the system build from a **clean** `build/` dir, or force it with `-DKDE_INSTALL_QMLDIR=lib/qt6/qml`. Verify the target before/after with a staged install: `DESTDIR=/tmp/stage cmake --install build && find /tmp/stage`.

Uninstall: `sudo xargs rm -v < build/install_manifest.txt` (plugin) and `sudo rm -rf /usr/share/plasma/plasmoids/com.github.tonymugen.plasma-show-stdout` (package), then `kbuildsycoca6 --noincremental`.

## Architecture

Two distinct layers communicate via condition variables:

**C++ plugin** (`plugin/`, namespace `PSSspace`) — compiled as shared library `plasma_show_stdout`:
- `runScript(path)`: free function wrapping `popen()`; returns stdout as a string, or an error message string if the script doesn't exist or the pipe fails — errors surface in the widget rather than throwing. The two error strings are produced via `translateMessage(messageId, argument)` (see the translation hook below) rather than hard-coded English, so they localize like the QML strings
- **Translation hook (keeps the module layer Qt-free).** `runScript`'s error text must be localizable, but `scriptModules.{hpp,cpp}` is deliberately Qt-/KI18n-free (so the fast `tests` target links no Qt). The seam: `setMessageTranslator(MessageTranslator)` installs a process-wide `std::function<std::string(messageId, argument)>` and `translateMessage(id, arg)` applies it (copying it under a `mutex` then invoking outside the lock, since workers translate on their own threads). The default translator is a built-in **English** fallback (so the Qt-free unit tests, which never install one, see English). The **Qt bridge** (`plasma-show-stdout.cpp`) installs the real translator once via `std::call_once` in `ScriptOutput`'s ctor: a lambda that maps the message ids (`"doesNotExist"`, `"failedToExecute"`) to `i18n("%1 does not exist", …)` / `i18n("Failed to execute %1", …)`. So the literal msgids that `xgettext` extracts live in the bridge .cpp (linked against `KF6::I18n`), and the module layer stays dependency-free.
- `truncateUtf8(text, maxCodepoints)`: free function (Qt-free) that shortens `text` in place to at most `maxCodepoints` **codepoints**, cutting only on a codepoint boundary so a multi-byte UTF-8 sequence is never split (which would render as `�`). Both modules call it on each run's output (so the per-module `outputLimit` is a character count, matching the config UI, not a byte count). Lead-byte lengths (1–4 bytes) are decoded with bit masks; stray/invalid bytes count as one codepoint so it always progresses; a fast path returns early when `text.size() <= maxCodepoints`
- `TimedModule`: calls `runScript` in a loop; acquires `mutex_`, writes to `outputString_`, notifies `signalToMain_`, then does `stopSignal_->wait_for(mutex_, refreshInterval_, stop_pred)` — if the predicate fires (spawning thread set `*stop_` and notified `stopSignal_`), the loop exits
- `SignalModule`: waits on `executionSignal_` with predicate `*execute_ || *stop_`; if stop, exits; otherwise resets `*execute_`, releases lock, runs script, reacquires lock, writes output, notifies `signalToMain_`; to trigger a run the spawning thread sets `*execute_ = true` and notifies `executionSignal_`; to stop it sets `*stop_ = true` and notifies the same CV
- Both classes are move-only; `mutex_`, `stop_`, and (for `SignalModule`) `execute_` are `shared_ptr` so the spawning thread retains access after constructing the module; `signalToMain_` and `executionSignal_` are `unique_ptr` — the spawning thread keeps a raw pointer before moving them in

**QML plugin** (`plugin/plasma-show-stdout.hpp`/`.cpp`):
- `ShowStdoutPlugin` (a `QQmlExtensionPlugin`) registers `PSSspace::ScriptOutput` as the QML type `ScriptOutput` at URI `com.github.tonymugen.plasmashowstdout` version 1.0.
- `ScriptOutput` (`QObject`) exposes a `text` `Q_PROPERTY` (`QString`, `NOTIFY textChanged`), a writable `delimiter` `Q_PROPERTY` (`QString`, `WRITE setDelimiter`, `NOTIFY delimiterChanged`, default `" | "`) — the single separator joining adjacent fragments; `setDelimiter` re-runs `rebuildCombinedText_()` and re-emits `text` from the existing fragments, so a delimiter change updates the display **without restarting any worker** (it runs on the GUI thread, like the bridge's rebuild, so no locking). It also exposes a `maxSignalOffset` `Q_PROPERTY` (`int`, `CONSTANT`, = `SIGRTMAX - SIGRTMIN`, so the config UI can size its signal spinbox without hard-coding glibc numbers), a `hostPid` `Q_PROPERTY` (`qint64`, `CONSTANT`, = `QCoreApplication::applicationPid()`), and a `hostName` `Q_PROPERTY` (`QString`, `CONSTANT`, read from `/proc/self/comm`). The config UI shows `hostName` in a `pkill --signal RTMIN+N <hostName>` trigger hint so the user signals the **actual** host process (`plasmashell`, or `plasmoidviewer`/`plasmawindowed` when testing) rather than guessing the name — a signal sent to the wrong process silently does nothing, which looks like a broken signal module. `pkill` (a real binary) is used rather than `kill` because the `kill` shell builtin (e.g. zsh's) does not accept an `RTMIN+N` signal spec; `/proc/self/comm` is exactly what `pkill <name>` matches against (kernel `comm`, ≤15 chars — `plasmoidviewer`/`plasmawindowed` are 14, so they fit). **Two constructors:** the QML entry point `ScriptOutput(QObject *parent)` — all `qmlRegisterType` can invoke — delegates to `ScriptOutput(std::vector<ModuleSpec>, QObject *parent)`, passing `defaultSpecs()` (a file-scope helper returning an **empty** vector). Both are `explicit`. `ModuleSpec` is a namespace-scope struct in `plasma-show-stdout.hpp` (so callers/tests can name it): a `Kind` enum (`Timed`/`Signal`), `script` path, `interval` (timed), `signalNumber` (signal), and per-module `outputLimit`. Each spec is built into a `std::variant<TimedModule, SignalModule>` and a `ModuleSlot`. Modules are run polymorphically via `std::visit([](auto &m){ m(); }, mod)` inside their worker thread (both types expose `void operator()() const`, so **`scriptModules.hpp` needs no base class**); the variant lives only in the spawn path, not in the slot.
- **Runtime (re)configuration.** Spawn/teardown is factored out of the constructor/destructor into `startModules_(std::vector<ModuleSpec>)` and `stopModules_()`, so the live module set can change after construction. The `Q_INVOKABLE void setModules(const QVariantList &specs)` is the path the QML config uses: it `stopModules_()`s, parses each `QVariantMap` (`kind` 0=Timed/1=Signal, `script` string, `interval` seconds, `signalOffset` → `signalNumber = SIGRTMIN + offset`, optional `outputLimit`; entries with an empty `script` are skipped), `startModules_()`s, then clears `text_` and emits so stale output disappears immediately. `stopModules_()` resets state for reuse (`slots_.clear()`, etc.) and is safe to call when nothing is running; `startModules_()` clears `*stop_` first since the instance may be restarting.
- A `ModuleSlot` (one per module, kept in `slots_` in display order) holds the worker + bridge threads, observer raw pointers into the worker (`changeSignal`, `outputBuffer`), the per-module `fragment` `QString`, and — for signal modules only — a per-module `execute` flag, an `executionSignal` observer, and the `signalNumber`. `slots_` is a `std::deque` (not `vector`) precisely because the bridges capture `&slot` fields: `deque` keeps references to existing elements valid when new ones are appended, so pointer stability does not depend on pre-reserving capacity.
- One `bridgeLoop_(ModuleSlot *slot)` runs per slot: it waits on the slot's change CV, snapshots+clears its `outputBuffer` under the shared `mutex_`, then posts a lambda to the GUI thread (`QMetaObject::invokeMethod(Qt::QueuedConnection)`) that updates the slot's `fragment`, calls `rebuildCombinedText_()` (joins all fragments in order with `delimiter_`), and `emit textChanged()`. Fragments are read/written only on the GUI thread. The bridge short-circuits redundant updates (`if (slot->fragment == newText) return;`).
- **Signal triggering:** there is no portable C++17 way to handle `SIGRTMIN+N` — `std::signal` covers only the six standard signals, and a handler may call only async-signal-safe functions (a `mutex`/`condition_variable` is not). So a file-scope POSIX `sigaction` handler does only a lock-free atomic store into `gSignalFired` plus `sem_post()`; a single `signalWaitLoop_` thread (serving all signal modules) drains the semaphore with `sem_wait` (retrying on `EINTR`), then `exchange(false)`s each fired flag and triggers the matching slot's `execute`/`executionSignal`. `gSignalFired` is a `std::array<std::atomic<bool>, _NSIG>` indexed by **raw signal number**: `_NSIG` (65) is a macro constant so it can size a `std::array`, whereas `SIGRTMIN`/`SIGRTMAX` are glibc runtime calls (`__libc_current_sigrt*()`) and cannot. The array's size is `constexpr`; the array object is not (the handler mutates it). (POSIX symbols are visible because ECM's `KDECompilerSettings` defines `_GNU_SOURCE`, despite `-std=c++17` without extensions.) The trigger semaphore (`gTriggerSemaphore`) and handlers are file-scope globals shared across **all** `ScriptOutput` instances, so `startModules_` only `sem_init`s / installs handlers / spawns `signalWaitLoop_` when a signal module is actually present, tracking that in `signalsActive_`; `stopModules_` undoes exactly what was set up. This lets a module-less instance — e.g. the throwaway `ScriptOutput` the config UI builds just to read `maxSignalOffset`/`hostName` — coexist with the running widget without touching the shared semaphore. (Two instances each with signal modules remain a pre-existing limitation of the global table.)
- `stopModules_()` (called by both the destructor and `setModules`) sets `*stop_ = true`, notifies all CVs, and `sem_post`s to wake the wait loop, then **joins every bridge and the signal-wait loop before the workers** — those observers reference worker-owned `condition_variable`/`std::string` objects (and, for the wait loop, `SignalModule`-owned `executionSignal`s) through raw pointers, so they must exit first. Then (only if `signalsActive_`) it points each used signal at `SIG_IGN` and `sem_destroy`s, so a late signal cannot post to a destroyed semaphore, and finally clears `slots_`.

**QML module URI vs KPackage applet ID** — these are deliberately distinct because QML import URIs must be dot-separated identifiers and may not contain hyphens (a hyphen in the URI triggers a QML parse error at the `import` line, which plasmashell reports as the same misleading "unknown older version of Plasma" error described above):
- QML module URI: `com.github.tonymugen.plasmashowstdout` — used in `qmldir`, in the QML `import` statement, and as the install subpath under `${KDE_INSTALL_QMLDIR}/`.
- KPackage applet ID: `com.github.tonymugen.plasma-show-stdout` — used by `plasma_install_package()`, in `metadata.json`'s `KPlugin.Id`, and as the argument to `plasmawindowed`/`plasmoidviewer`.

**QML plugin module** (`plugin/qmldir`) maps the URI to the `plasma_show_stdout` shared library and declares `classname ShowStdoutPlugin`. Both the library and `qmldir` install to `${KDE_INSTALL_QMLDIR}/com/github/tonymugen/plasmashowstdout`.

**Plasma package** (`package/`) installs under the applet ID `com.github.tonymugen.plasma-show-stdout` via `plasma_install_package()`. `package/contents/ui/main.qml` is a `PlasmoidItem` with a `compactRepresentation` (shown inline in a panel, like the Digital Clock's time) and a `fullRepresentation` (scrollable monospace `Label`). The **compact** rep renders the combined output as a single elided monospace `Label`; in a panel the applet width comes from the root's `Layout.minimumWidth`/`Layout.preferredWidth` (**not** `implicitWidth`, which the panel ignores — without the `Layout` properties the panel gives a near-square default and the text truncates), both driven off `outputLabel.implicitWidth` so the item grows/shrinks with the output. It falls back to the terminal icon (square: width == `height`) only when there is nothing to show — configured-but-no-output-yet — so the applet never collapses to zero width, and shows the dimmed "Add scripts" prompt when no scripts are configured; clicking it toggles `expanded` to open the full popup. The **full** rep is the scrollable wrapped `Label` (used on the desktop and in the click-to-expand popup), bound to `scriptOutput.text` with the same dimmed/italic "Add scripts" fallback; its colors track the active scheme via `Kirigami.Theme.View` (with `inherit: false`). Both placeholders key off `root.scriptCount` — the count of configured entries with a non-empty path, set by `applyConfig()` — **not** off `text` being empty, so a configured-but-idle module (e.g. an untriggered signal) keeps showing output rather than reverting to the prompt. The applet is a **normal panel widget** (no `X-Plasma-NotificationAreaCategory`): it is meant to sit in a panel and show its output inline; the system-tray category was removed because the tray forces the compact rep into a tiny square, clipping the text. `Plasmoid.status` is pinned to `ActiveStatus` (harmless for a panel widget). The `ScriptOutput { id: scriptOutput }` lives at the **root** `PlasmoidItem` (not inside `fullRepresentation`) so the configured modules run whether or not the widget is expanded; `main.qml`'s `applyConfig()` `JSON.parse`s the `modules` config string into the `setModules` argument, and a separate `applyDelimiter()` pushes `Plasmoid.configuration.delimiter` to `scriptOutput.delimiter` (cheap — re-joins without restarting workers). Both run on `Component.onCompleted`; a `Connections { target: Plasmoid.configuration }` block routes `onModulesChanged` → `applyConfig()` and `onDelimiterChanged` → `applyDelimiter()` (kept separate so editing the delimiter doesn't tear down and respawn every module).

**Package config** (the full, ordered module list):
- `package/contents/config/main.xml` — KConfigXT schema, group `General`, a **single** `modules` (String) entry holding the whole list as a **JSON array** of `{ kind (0=Timed/1=Signal), script, interval (seconds), signalOffset (RTMIN+N), outputLimit (chars) }` objects, default `[]`. A variable-length list does not fit a fixed set of scalar `cfg_<key>` entries, so it lives in one string key. Objects from a config saved before `outputLimit` existed simply omit that key; `main.qml` omits it from the `setModules` entry when absent so the C++ side falls back to `ModuleSpec`'s default of 300 (rather than receiving an invalid `0`, which would truncate to nothing). A separate `delimiter` (String, default `" | "`) entry holds the single output separator; surrounding spaces are significant (do not trim it). A `fontFamily` (String, default `"monospace"`) entry sets the display font for both representations; the labels bind `font.family` directly to `Plasmoid.configuration.fontFamily` (falling back to `"monospace"` if empty), so it needs no C++ and applies on Apply without a reinstart. The config UI offers a `Display font` row (text field + native `Dialogs.FontDialog` picker that yields `selectedFont.family`) and a live sample-text preview so missing glyphs are visible while choosing.
- `package/contents/config/config.qml` — a `ConfigModel` with one `ConfigCategory` ("General") sourcing `configGeneral.qml`.
- `package/contents/ui/configGeneral.qml` — a `KCM.SimpleKCM` whose content is a `ColumnLayout` + `Repeater` over an in-memory `ListModel` (`modulesModel`), top-level delimiter and display-font `TextField`s (`cfg_delimiter` and `cfg_fontFamily`, plain scalars handled by the standard `cfg_<key>` alias; the font row adds a `Dialogs.FontDialog` picker and a sample-text preview label), then one `Kirigami.AbstractCard` per module (script `TextField` + `Browse…` `FileDialog`, Timed/Signal `ComboBox`, conditional interval/offset `SpinBox`, an output-limit `SpinBox` that applies to both kinds, and a "Remove" button), plus an "Add script" button that appends a blank timed module. The framework can't auto-bind a dynamic list to `cfg_<key>` scalars, so the list lives in one plain `property string cfg_modules`: `load()` decodes that JSON into `modulesModel` on `Component.onCompleted`, and every edit calls `modulesModel.setProperty(...)` then `serialize()`, which re-encodes the model into `cfg_modules` — that single string change is what Plasma persists and what marks the page dirty (enabling Apply). **Removal is deferred via `Qt.callLater`** (the Remove button calls `configPage.removeModule(i)` through it): a `Repeater` destroys the delegate hosting the button the instant the row is removed, and destroying an object mid-handler aborts the rest of the inline handler — so an inline `modulesModel.remove(i); serialize()` would drop the `serialize()` and never mark the page dirty (Apply would stay disabled). Running it from `configPage` after the click handler returns avoids that. Card delegates use **required properties** matching the ListModel roles (`index`/`kind`/`script`/`interval`/`signalOffset`) to stay unambiguous inside nested control scopes (bare role names can clash with e.g. `ComboBox.model`). The `FileDialog` tracks a `targetIndex` so one shared dialog can fill any row. The signal offset is converted to a raw signal **C++-side** in `setModules` (QML can't know `SIGRTMIN`); a module-less `ScriptOutput { id: pluginInfo }` probe supplies `maxSignalOffset` for the spinbox ranges and `hostName` for the trigger hint (`pkill --signal RTMIN+N <hostName>`).

## Conventions

- C++ standard: 17 (no extensions)
- Compiler warnings are maximally strict (see `CMakeLists.txt` for the full list); new code must compile cleanly
- Address and leak sanitizers are auto-enabled in `Test` builds when the compiler supports them
- Namespace: `PSSspace` for all plugin C++ code
